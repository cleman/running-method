# spec/fixtures-input — complete persona inputs (v5.2)

One file per persona of `13-worked-examples.md` and `14-validation-plan.md`, valid against `spec/schema/fixture-input.schema.json`. **Inputs only.** No file holds an expected verdict, plan, week value or message: expected outputs are written independently by the Oracle session (`oracle/`, blocker B-5).

## How to read a fixture

- `input`: the generator input at day 0 (`spec/schema/input-profile.schema.json`).
- `behaviour`: how the runner logs afterwards. `as_planned` = every planned session ticked "done as planned" the same evening, RPE at the target of its effort (`ses.target_rpe`), pain tap answered "No", next-morning prompt "No", stomach 0/10 at the planned intake on fuelling-practice runs, level-test questions answered yes / yes / no pain. `scripted` = the same, plus the listed deviations (results, illness, missed weeks…). `day0_only` = only the first call matters. With `replan: weekly` the harness calls the generator every Monday with the log so far; 13's week tables show each week as published at its Monday (13 §0, v5.2).
- `provenance`: every input value is tagged `spec: <13/14 line>`, `derived: …` or `invented: …`. **Invented values must be reviewed by a second reader** (gap/oracle.md §7); they were chosen to complete the persona, never to reach a particular result.
- `release`: the release profile the goal needs (MVP = 5K, 10K, HM).

Common choices (all `invented` unless a persona says otherwise): day 0 is Monday 2 Nov 2026, so plan week 1 starts on day 0 and a race "in N weeks" is on the Sunday (Saturday when the persona races on Saturday) of week N; time zone Europe/Paris; PAR-Q+ items are **placeholders** `parq_placeholder_01…07` answered "no" (the licensed text is not in the repository, blocker B-1; item 02 stands for the chest-pain item); onboarding symptom questions answered "no"; logs are entered the same evening (measured).
